04 / 技能配置

第四件：技能不是按「这个地点能回答什么」配的

个人版问人流、空车位、堵不堵，靠的是构成上所挂相机的技能。生产里技能跟镜头走：画面上能跑什么模型，就挂什么。和实体类型、问法对不齐。关系抽样 871 块构成上，人员流量 1491 次、车流量 937、车辆排队 697；停车位状态只有 45 次。列表 4319 条实体的 skillId 全空；时序抽样 24 条标题全是「人流量」，含停车场。

同一块构成，技能堆在一起

现状：构成
六角广场 · 室外区域
1 块构成 · 44 路相机
挂了：人员流量、人员排队、停车位状态、儿童行为、共享单车、场地设施占用、空座位识别、营业状态、车流量、车辆排队。
判断：一块「室外」把商场外场所有模型都接上了。问人流、问停车、问营业会打到同一锅画面，无法对应「这个构成回答哪一个问题」。
现状：构成

05 / 建议

这套建模应该怎么建

不是另起一套。SeeTime 个人版已经定死：用户点名谁就答谁；概况只带下一级可提问地点，不带构成、不跳孙实体；技能和画面挂在构成上，选中实体后再取。数据中心要把「可提问地点」和「观察面」建准，并让「哪里有卫生间」这类设施问法能召回到从属实体。

对象是什么个人版怎么用例子
实体 用户会单独点名的地点 主实体，matchedIndices 第 1 个 总统府、少林寺、地藏禅寺、美龄宫停车场、紫金山索道
从属实体 真实包含的下一级地点，含设施点 问父概况时追加一层；问「哪里有卫生间」必须能召回卫生间从属 少林寺下的索道、园内停车场、卫生间；六角广场下的按楼层卫生间
关联 旁边配套，不是包含 道路概况追加路口；景区/商场不能承载停车时找兄弟停车场 双龙大道 ↔ 路口；景区 ↔ 园边停车场
构成 这个实体从哪几面看；相机和技能挂在这里 概况/人流禁止进 matchedIndices；选中实体后由下游取画面 门口、湖面、步道、停车位、扶梯。类型是观察面，不是景点

四者互斥：同一对象不能既是构成又是实体。扶梯、路灯路段停在构成；卫生间做成从属实体，镜头做成该卫生间的构成。

第一问：镜头对着的是哪个地点

拍到星巴克，先认定「这是星巴克」这条实体（没有就新建，并挂到商场下）。不是先把它建成构成。

第二问：这一路是这个地点的哪一面

同一家星巴克可以有门口、座位区。每一路相机只生成该实体下的构成、图、技能。扶梯、路灯路段没有可提问地点，构成才挂在商场/道路上。

顺序是地点 → 观察面。现在的做法是镜头 → 直接切构成，所以星巴克会停在六角广场的构成里，个人版问店名召不回。

个人版问法，对应到这棵树上

问嵩山
容器可以 0 相机
答直接从属：少林寺、嵩阳、中岳。不跳到少林索道下的商户。

索道、游客中心、园内停车场、卫生间。塔斯汀这种店铺也可以建成从属；问「少林寺怎么样」默认不把店铺铺开，用户点名店名再答那家店。

硬约束

从属写父 ID

园里真实存在的点必须出现在该地点从属里。少林寺塔斯汀、美龄宫停车场、牛首山希尔顿，不能只靠名字像。

构成与从属禁止同名

西天目停车场、水岸听风、卫生间，选一边。一路相机默认一个构成。

技能跟问法走

停车场构成挂停车位状态；景区现场挂人流/风光；扶梯不要儿童行为。实体级时序与构成技能一致。
