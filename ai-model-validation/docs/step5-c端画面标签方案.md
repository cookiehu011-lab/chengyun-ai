# SeeTime Step5：C 端画面标签方案

> 版本：2.1  
> 目的：让相机截帧标签能回答 C 端用户问题，而不是盘点画面物体。  
> 代码：`data/scene_tag_vocab.json` + `scripts/step5_scene_tags.py`  
> 校验 UI：图片下方展示「定位锚点 / 当下状态」

---

## 1. 目标与原则

用户会问的典型问题：

- 这条路堵不堵？车多不多？
- 停车场好不好停？有没有空位？
- 这家店开没开？灯亮不亮？门口人多不多？
- 公园 / 商场人多不多？
- 现在画面能不能看清？

因此标签必须满足：

1. **能回答问题**：每个 tag 应对应一类用户问法。
2. **闭集输出**：key 只能从词表选，禁止自造（锦旗、立柱、水印等）。
3. **按场景取舍**：卫生间走廊不要打空闲车位；停车场不要硬打营业观感。
4. **多时段覆盖**：有几张抽帧，相关动态标签就要覆盖对应 slots。
5. **负向默认省略**：无施工、无排队、清晰、无外摆不输出，避免填空噪音。
6. **summary 与 tags 对齐**：摘要承诺能看的点，tags 里必须有。

---

## 2. 字段结构

每路相机输出：

| 字段 | 说明 |
|---|---|
| `scene_type` | 场景类型（闭集，单选） |
| `scene_viewpoint` | 视角（闭集） |
| `scene_summary` | 一句人话：这路相机能帮用户看什么 |
| `static_tags` | 定位锚点（跨时段基本不变） |
| `dynamic_tags` | 当下状态（随抽帧变化，必带 `slots`） |
| `confidence` | 有把握 / 没把握 |

动态 tag 单条结构：

```json
{
  "key": "拥堵观感",
  "value": "缓行",
  "level": null,
  "slots": ["noon", "afternoon"],
  "confidence": "有把握"
}
```

- `slots` 仅允许：`morning` / `noon` / `afternoon`（对应输入第 1/2/3 张抽帧，不是挂钟时间）。
- 画面即使是夜里，也写帧位名，禁止 `night`。
- `车流密度` / `人气` 可用 `level`：无/少/中/多/密；其它 key 优先用 `value`。

## 3. 场景类型（scene_types）

| 场景 | 定义 | 优先回答 |
|---|---|---|
| 道路 | 主体是车行道路面/路段通行 | 拥堵观感、车流密度、人气、施工挡路、画面可看性 |
| 路口 | 交叉口、信号灯控制的交叉通行 | 同上 |
| 停车场 | 地面或库内以车位停放为主体 | 空闲车位、车流密度、画面可看性 |
| 地库通道 | 地下车库行车通道为主 | 空闲车位、车流密度、画面可看性 |
| 店招门脸 | 主体可读店招，用户主要问这家店 | 营业观感、店招亮灯、外摆/堂食观感、人气、排队观感、画面可看性 |
| 人行道 | 步行空间为主 | 人气、施工挡路、画面可看性 |
| 广场 | 开阔公共广场 | 人气、画面可看性 |
| 公园/景区 | 绿地、步道、景点休憩区 | 人气、画面可看性 |
| 小区内部 | 住宅小区内部道路/庭院 | 人气、画面可看性 |
| 电梯厅/楼道 | 室内走廊、电梯厅；**含卫生间外走廊** | 人气、画面可看性 |
| 商场内部 | 商场公共区内部 | 人气、排队观感、画面可看性 |
| 公交/交通场站 | 地铁口、公交站等 | 人气、车流密度、画面可看性 |
| 卫生间 | 能看到卫生间入口/隔间本身 | 人气、画面可看性 |
| 卫生站/服务大厅 | 社区卫生服务中心/卫生所大厅诊区 | 人气、排队观感、画面可看性 |
| 其他 | 无法归入以上 | 人气、画面可看性 |

补充规则：

- 相机名含「卫生间」但画面只是门外走廊 → 选 **电梯厅/楼道** 或 **商场内部**，不要硬标卫生间。
- 相机名是店名但画面主体是马路 → 选 **道路/路口**；店招仅作锚点。
- 卫生站空走廊：**不要硬打营业观感**。

## 4. 定位锚点（static_tags）

只保留能帮用户「定位这是哪 / 看什么」的锚点，不做设施盘点。  
**有可读字或明确地标时，至少打 1 个，禁止无故空锚点。**

| key | 定义 | 写法 |
|---|---|---|
| 主店招 | 画面最醒目可读的店名/招牌字 | value=读到的字；名称冲突以画面为准；道路旁临街店招也应打 |
| 路名/指示牌 | 路名牌、导向牌 | value=读到的字；无牌但路名极明确时可没把握补 |
| 出入口标识 | 卫生间/电梯/地铁口等功能指示 | 如男卫、4号口；不要把普通玻璃门写成出入口 |
| 地标锚点 | 城墙门洞、标志建筑等 | 可定位物 |
| 停车出入口 | 道闸、车库入口、岗亭 | 停车场/地库优先 |
| 场所名 | 画面可读场所名（含清晰场所水印） | 如「1号地下车库」「后宰门卫生服务中心大厅」；禁止运维编码 |

场景优先：

- 道路/路口 → 路名、临街店招、地标  
- 店招门脸 → **必须有主店招**  
- 停车场/地库 → 停车出入口或场所名  
- 卫生间走廊 → 出入口标识  
- 卫生站 → 场所名  

### 禁止作为锚点 / 标签

运维编码水印（Camera 09、玄板0122、固枪外治）、绿化/树木、建筑立面、立柱/警示条、车道线、斑马线、护栏、遮阳棚、室内家具设备清单。  
清晰的**场所名水印**可以用 `场所名`，不要用旧的「水印文字」盘点标签。

## 5. 当下状态（dynamic_tags）

| key | 回答的问题 | value 建议 | 默认省略 |
|---|---|---|---|
| 拥堵观感 | 堵不堵 | 畅通 / 缓行 / 拥堵 / 说不清 | — |
| 车流密度 | 车多不多 | 无/少/中/多/密（或 level） | — |
| 人气 | 人多不多 | 无/少/中/多/密（或 level） | — |
| 空闲车位 | 好不好停车 | 松 / 紧 / 满 / 看不清 | — |
| 营业观感 | 开没开 | 像在营业 / 像已打烊 / 说不清 | 空走廊勿硬打 |
| 店招亮灯 | 灯亮没亮 | 亮 / 灭 / 说不清 | — |
| 外摆/堂食观感 | 有没有外摆/人坐 | 有外摆 / 无外摆 / 有人坐 / 说不清 | `无外摆` |
| 排队观感 | 排不排队 | 无 / 短 / 长 / 说不清 | `无` |
| 施工挡路 | 有没有施工挡路 | 无 / 有挡路 / 说不清 | `无` |
| 画面可看性 | 能不能看清 | 清晰 / 偏暗 / 看不清 | `清晰` |

说明：

- 「默认省略」由规范化逻辑自动过滤，即使模型输出也会丢弃。
- 摘要写了「夜间偏暗 / 看不清」时，必须有对应的 `画面可看性`。
- 店招场景摘要写了亮灯/外摆，tags 必须落地，不能只写在 summary。

---

## 6. 打标规则（必须遵守）

1. **多时段覆盖**  
   本次成功输入的每个 slot，相关动态 key 都应覆盖（可用多条拆分不同 value）。  
   禁止只答 morning，却在 summary 提夜间。

2. **负向默认省略**  
   `施工挡路=无`、`排队观感=无`、`画面可看性=清晰`、`外摆=无外摆` 不入库。

3. **summary ↔ tags 对齐**  
   summary 承诺的观察点，必须能在 static/dynamic 中找到。

4. **名称冲突**  
   相机名 ≠ 画面主店招时：主店招以画面为准，reason 注明冲突。

5. **场景相关**  
   只打 `scene_question_map` 中该场景相关的动态 key。

6. **置信度降级（后处理）**  
   - 可用帧 ≥2，但关键动态 key 只覆盖 1 个 slot → `没把握`  
   - summary 含偏暗/夜间/看不清，却无画面可看性 → `没把握`  
   - scene=其他 且无锚点 → `没把握`

## 7. Prompt（运行时模板）

以下由 `build_prompt(row, available_slots)` 生成；`{...}` 为运行时替换。

```text
你是 SeeTime 的 C 端画面问答助手。用户会问：堵不堵、有没有空位、店开没开、人多不多、能不能看清。
本次实际输入抽帧 slots（按顺序对应图片）：{slot_zh}
只输出一个 JSON 对象，不要 Markdown，不要解释。

核心原则：
1. 标签必须能回答 C 端问题，禁止做物体盘点。
2. 禁止打这些：水印文字、绿化/树木、建筑立面、立柱/警示条、车道线、斑马线、护栏、遮阳棚、室内家具/设备清单。
3. key 必须从闭集选择，不许自造 key。
4. 只打与当前场景相关的标签；不相关就省略。
5. 动态标签只描述这些抽帧里看见的；每个相关动态 key 必须覆盖本次全部可用 slots（可用多条拆分不同 value/level）。
6. slots 只能用本次给出的帧位名；即使画面是夜里也写 morning/noon/afternoon，禁止 night/白天。
7. 默认负向不要输出：施工挡路=无、排队观感=无、画面可看性=清晰、外摆=无外摆 —— 这些省略即可；有异常或说不清再打。
8. scene_summary 一句人话写「能帮用户看什么」；summary 提到的点必须在 tags 里有对应项。
9. 锚点禁止用水印/相机编码/机构全称冒充；出入口标识只用于卫生间/地铁口/电梯等功能指示。
10. 卫生站/服务大厅、电梯厅/楼道：优先人气；不要对空走廊硬打营业观感。
11. 卫生间外走廊应选「电梯厅/楼道」或「商场内部」，不要仅因名字含卫生间就标成卫生间。
12. 相机名与画面主店招冲突时：主店招以画面为准，并在 reason 里点明冲突。

可用场景类型（闭集）：道路、路口、停车场、地库通道、店招门脸、人行道、广场、公园/景区、小区内部、电梯厅/楼道、商场内部、公交/交通场站、卫生间、卫生站/服务大厅、其他
可用视角（闭集）：俯拍、平视、斜视、近景门脸、通道纵深、其他
定位锚点 static_tags：主店招、路名/指示牌、出入口标识、地标锚点、停车出入口
当下状态 dynamic_tags：拥堵观感、车流密度、人气、空闲车位、营业观感、店招亮灯、外摆/堂食观感、排队观感、施工挡路、画面可看性

动态 value 建议：见词表 dynamic_value_hints
按场景优先回答：见词表 scene_question_map

本路信息：camera_id / camera_name / 已有分类 / 已有画面一句

输出 JSON 示例：
{
  "scene_type": "店招门脸",
  "scene_viewpoint": "斜视",
  "scene_summary": "街边餐饮门脸，可看店招亮没亮、门口人气",
  "static_tags": [
    {"key": "主店招", "value": "有鱼", "confidence": "有把握"}
  ],
  "dynamic_tags": [
    {"key": "营业观感", "value": "像在营业", "slots": ["noon", "afternoon"], "confidence": "有把握"},
    {"key": "店招亮灯", "value": "灭", "slots": ["morning"], "confidence": "有把握"},
    {"key": "店招亮灯", "value": "亮", "slots": ["afternoon"], "confidence": "有把握"},
    {"key": "人气", "level": "少", "slots": ["morning", "noon", "afternoon"], "confidence": "有把握"},
    {"key": "画面可看性", "value": "偏暗", "slots": ["morning"], "confidence": "有把握"}
  ],
  "confidence": "有把握",
  "reason": "简短说明；若名称与店招冲突请写明"
}
```

机器闸门（`normalize_tags`）：

1. 丢弃不在闭集的 key  
2. 丢弃 `dynamic_omit_defaults` 负向默认  
3. slots 过滤到本次真实可用帧  
4. 多时段塌缩 / summary 不对齐 → 降为没把握

## 8. 流程位置

```
第1步 接入截帧
  → 第2步 价值+分类
  → 第3步 实体聚合
  → 第4步 发布门禁（预留）
  → 第5步 画面理解（本方案）
```

跑批：

```bash
# 仅重跑已打过的
python scripts/step5_scene_tags.py --retag --limit 25 --workers 2

# 单路
python scripts/step5_scene_tags.py --id 11
```

UI：详情页截帧正下方展示定位锚点 / 当下状态。

## 9. 验收清单

人工抽检时关注：

- [ ] 标签能否直接回答该场景的用户问题  
- [ ] 有 2～3 帧时，关键动态是否覆盖多 slot  
- [ ] 是否出现水印/绿化/立柱等盘点标签  
- [ ] 是否出现无意义的「畅通填空」以外的负向噪音（无施工/清晰）  
- [ ] 名称冲突时主店招是否跟画面一致  
- [ ] summary 与 tags 是否一致
